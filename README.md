# claude good morning

Every morning at 9:00, posts a Discord message with:

- Today's menu from [U Krkovice](https://ukrkovice.cz/j%C3%ADdeln%C3%AD-l%C3%ADstek/j%C3%ADdeln%C3%AD-l%C3%ADstek) (soups + daily specials)
- Czech name day (svátek)
- Weather forecast for Prague, with a morning/midday/afternoon/evening breakdown
- A stock check-in (default: Tenax Therapeutics, NASDAQ: TENX)
- Prague public transit (PID) disruptions affecting a configurable list of stops
- A historical "on this day" fun fact, generated by the `claude` CLI

Runs locally on macOS via `launchd`, with a scheduled wake (`pmset`) so it fires even if the Mac was asleep.

## Prerequisites

- macOS
- Python 3.11+ (`python3 --version`)
- [Claude Code](https://claude.com/claude-code) installed and logged in (`claude` on your `PATH`, already authenticated with your subscription — the launchd job runs as your user, so it reuses that login)
- A Discord server where you can create a webhook

## 1. Get a Discord webhook URL

In Discord: **Server Settings → Integrations → Webhooks → New Webhook**, pick the target channel, and copy the webhook URL.

## 2. Install Python dependencies

```bash
pip3 install --user requests beautifulsoup4 python-dotenv
```

Note the exact `python3` this installs into (`which python3`) — you'll need its absolute path in step 5 if you have multiple Python installs (e.g. both a Homebrew one and a python.org one), since `launchd`'s `PATH` may not resolve to the one with these packages.

## 3. Configure secrets

Create a `.env` file next to `claude_good_morning.py`:

```
DISCORD_WEBHOOK_URL=https://discord.com/api/webhooks/...
```

## 4. Customize for your situation

Edit the constants near the top of `claude_good_morning.py`:

| Constant | What it controls |
|---|---|
| `MENU_URL` | The restaurant menu page to scrape (currently U Krkovice's Framer-built page — scraping logic assumes that site's HTML structure) |
| `PRAGUE_LATITUDE` / `PRAGUE_LONGITUDE` | Weather location (default: Prague) |
| `STOCK_SYMBOL` / `STOCK_NAME` | Which stock to check in on |
| `TRANSIT_STOPS` | List of PID stop names to filter transit disruptions to |
| `DAYPARTS` | Which hours of the day to show in the weather breakdown |

## 5. Make the script executable and test it manually

```bash
chmod +x claude_good_morning.sh claude_good_morning.py
./claude_good_morning.sh
cat /tmp/claude_good_morning.log
```

Check Discord — you should see a message. If `python3` in the `.sh` file resolves to the wrong interpreter (missing packages), edit `PYTHON_BIN` in `claude_good_morning.sh` to the absolute path from step 2.

## 6. Schedule it with launchd

Cron was intentionally **not** used here — cron can't run while the Mac is fully asleep and won't catch up on a missed run. `launchd` will fire the job as soon as the Mac wakes if the exact scheduled minute was missed.

Create `~/Library/LaunchAgents/com.<you>.goodmorning.plist` (this must be a **LaunchAgent** in your user's `~/Library/LaunchAgents`, not a system-wide LaunchDaemon — a LaunchDaemon runs as root and won't have access to your `claude` CLI login):

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.<you>.goodmorning</string>

    <key>ProgramArguments</key>
    <array>
        <string>/bin/bash</string>
        <string>/absolute/path/to/claude_good_morning.sh</string>
    </array>

    <key>StartCalendarInterval</key>
    <dict>
        <key>Hour</key>
        <integer>9</integer>
        <key>Minute</key>
        <integer>0</integer>
    </dict>

    <key>StandardOutPath</key>
    <string>/tmp/claude_good_morning_launchd.log</string>
    <key>StandardErrorPath</key>
    <string>/tmp/claude_good_morning_launchd.log</string>

    <key>RunAtLoad</key>
    <false/>
</dict>
</plist>
```

Load it:

```bash
launchctl load -w ~/Library/LaunchAgents/com.<you>.goodmorning.plist
```

Test it fires correctly without waiting for 9am:

```bash
launchctl start com.<you>.goodmorning
# wait ~20s for the claude CLI call to finish, then:
cat /tmp/claude_good_morning.log
```

To change the schedule later, edit the plist and reload:

```bash
launchctl unload ~/Library/LaunchAgents/com.<you>.goodmorning.plist
launchctl load -w ~/Library/LaunchAgents/com.<you>.goodmorning.plist
```

## 7. Schedule a wake so it actually fires at 9am

Without this, the job only runs if the Mac happens to already be awake at 9am (or catches up whenever it's next opened).

```bash
sudo pmset repeat wakeorpoweron MTWRFSU 08:58:00
```

This wakes the Mac at 8:58 (a couple minutes early on purpose — waking from sleep isn't instant for networking, so the buffer lets Wi-Fi fully reconnect before the 9:00 job fires and starts making HTTP requests).

Verify it's set:

```bash
pmset -g sched
```

Caveats:
- Works reliably on AC power, including with the lid closed.
- On battery, macOS doesn't 100% guarantee scheduled wake on every model/macOS version — it's the best mechanism available locally, but not an absolute guarantee. If that matters, running this in the cloud (e.g. a scheduled GitHub Actions workflow) removes the dependency on the laptop's power/sleep state entirely, at the cost of needing a separate Anthropic API key for the `claude` CLI step (your Claude subscription login won't work in a headless CI runner).

## Files

| File | Purpose |
|---|---|
| `claude_good_morning.py` | All the fetching/formatting/posting logic |
| `claude_good_morning.sh` | Sets up `PATH`/logging, then runs the Python script — this is what `launchd` invokes |
| `.env` | `DISCORD_WEBHOOK_URL` (not committed to git) |
| `~/Library/LaunchAgents/com.<you>.goodmorning.plist` | The schedule |

## Troubleshooting

- **Nothing posted, no log entry**: check `launchctl list | grep goodmorning` — if it's not listed, the plist didn't load (check `launchctl load` output for errors, and validate the plist with `plutil -lint <path>`).
- **Log shows a Python traceback about a missing module**: `PYTHON_BIN` in `claude_good_morning.sh` points to a Python without the required packages — see step 2.
- **Menu/weather/stock/transit sections show "(nepodařilo se načíst)" fallback text**: that data source failed to fetch (site down, API change, etc.) — the script degrades gracefully per-section rather than failing the whole run. Check `/tmp/claude_good_morning.log` for the underlying exception, printed to stderr.
- **Job didn't fire near 9am at all**: check `pmset -g sched` to confirm the wake schedule is still set (it can be cleared by macOS updates or manual `pmset` changes) and `pmset -g log | tail` around the relevant time to see if the Mac actually woke.
